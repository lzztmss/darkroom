# ADR 0003：分析结果阅读密度与首轮延迟

日期：2026-09-21  
状态：执行中

## 背景

本地 MVP 的结果页右侧同时显示五维评分、每维证据和每维建议；下方又显示完整的可执行建议，造成重复和阅读负担。模型返回的标注字段偶尔出现英文，填写的创作意图虽然已经传给模型，却没有在结果页形成明确的可见反馈。单次视觉请求的输出上限和图片副本也需要收紧，但不能牺牲结构化校验和低置信度降级。

## 决策

1. 评分卡只保留分数、置信度和一句证据摘要；完整建议统一放在下方“可执行建议”，避免重复。
2. 评分条沿用本地 MVP 规格：85–100 使用灰绿色、75–84 使用暖灰金、0–74 使用低饱和砖红。颜色只作快速扫读，不代表照片的绝对好坏。
3. 填写创作意图时，结果页显示原始意图；模型必须在主观判断中明确回应意图，并提供另一种合理解读。意图不能改写事实或直接改变分数。
4. Prompt 要求所有用户可见的模型文本使用简体中文；必要的艺术家姓名、作品名或画面内原文可保留，并附中文解释。
5. 第一轮延迟优化采用可回滚的小步调整：分析副本最长边从 1600px 降至 1440px、目标体积从约 1.2MB 降至约 0.9MB，结构化输出上限从 3200 tokens 降至 2400 tokens；思考模式仍由环境变量控制，默认关闭。
6. 模型输出先做本地 JSON 提取；只有解析失败或 schema 校验失败时才补发一次修复请求。正常响应保持单次请求，不增加常态延迟。非关键的裁切候选若超过 25% 损失则降级为 omit，不让整张分析失败。

## 约束与验证

- 不通过前端截断文字伪造“变快”；模型字段仍需完整通过 schema 校验。
- 低置信度坐标继续降级为文字，不为了增加画面元素而补造框线。
- 使用固定照片评测集比较结构化通过率、主观判断完整度、中文文本比例和请求耗时；若质量回归，先恢复图片或输出预算，再单独调整模型。
- 服务端记录模型名、输入体积、输出字符数和总耗时；日志不得包含照片内容、API key 或精确定位信息。

## 首轮实测

- 公开固定样例通过本地 `/api/analyze`，返回 `local-v2` 结构化结果，主观判断为 2 条。
- 两次请求的模型阶段分别约 32.2 秒和 36.7 秒；Next 请求处理开销为毫秒级，当前主要瓶颈是模型推理。
- 输出没有出现整句英文；保留的拉丁字母内容为艺术家姓名、作品名或摄影术语，并附有中文解释。
- 本轮建立了可比较的耗时基线，但没有旧 Prompt 的同条件数据，因此不宣称已达到延迟目标。下一轮使用同一固定集比较更快的视觉模型或服务档位。
- 格式容错测试覆盖：Markdown/说明文字包裹的 JSON、截断 JSON 的一次修复请求、正常路径单请求，以及超限裁切候选的安全降级。
