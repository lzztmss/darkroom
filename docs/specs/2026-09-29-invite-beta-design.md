# 小红书邀请内测版设计方案

日期：2026-09-29  
状态：待用户审阅  
目标：从本地 MVP 进入 5–10 人邀请内测

## 1. 产品范围

本阶段验证摄影爱好者是否愿意上传照片、认真阅读点评，以及点评能否帮助他们决定下一次拍摄怎么做。通过小红书内容招募体验者，服务本身先保持邀请码访问。

### 结果页

- 保留五个评分维度：构图、光线、色彩、叙事、技术质量。
- 不展示“意图与语境完成度”评分。
- “可直接观察的事实”和“基于摄影知识的解释”合并为一个有证据的点评区域，避免重复罗列。
- 不增加“先看这里 / 现在该做什么”独立板块。
- 作者识别作为分析前置步骤；高置信度识别结果及其对评分的有限影响只在“综合参考”中解释，不单开作者识别栏目。无法确认时明确写“未能可靠识别”，不猜测作者。
- 移除参数调色预览功能。
- 引导线置信度低于 85% 时不显示；其他标注遵循既有低置信度降级规则。
- 分数整体保持鼓励性，但必须受照片证据约束，不能用统一加分掩盖问题。

### 内测入口

- 仅通过邀请码进入；每个邀请码绑定一个内测名额和分析次数。
- 不开放公开注册、支付、社区、作品墙或用户照片训练授权。
- 每次分析提供反馈入口；反馈默认只用于产品质量改进，不自动授权公开或模型训练。

## 2. 推荐的首版架构

沿用现有 Next.js 应用，采用单体 Node 服务，不拆微服务。生产数据组件部署在同一中国大陆地域：

```text
小红书招募内容 → 邀请码入口 → Next.js 应用
                               ├─ 会话、邀请名额、每日额度、限流
                               ├─ 分析 API → 统一模型网关 → 经确认的境内视觉模型
                               ├─ PostgreSQL：账户、额度、点评元数据、反馈
                               ├─ 私有对象存储：短期分析图像
                               └─ 日志、错误告警、预算上限、管理员停用开关
```

选择具体云厂商前，先核实部署主体、域名、备案资格、数据地域和模型服务条款。部署与模型区域确认后，再购买满足备案要求的最小资源；不预购高配机器。大陆公众网站开放访问前完成适用备案。

生产模型供应商与图片数据位置必须一并确认。默认方案是境内存储和境内模型服务；若无法确认数据不出境，则不接收真实用户照片。模型密钥只保存在服务端密钥配置中。

## 3. 访问控制与额度

- 邀请码只在服务端保存其哈希、有效期、状态和额度；成功兑换后签发 HttpOnly、Secure、SameSite 会话 Cookie。
- 服务端按账户和 IP 限速，并设单账户每日分析上限和全站每日预算上限。
- 同一请求使用幂等键；重复点击、刷新或网络重试返回同一结果，不重复调用模型或扣减额度。
- 管理员可暂停单个账户、邀请码或全站分析接口。
- 未登录、额度耗尽、模型余额不足、请求频率过高和模型繁忙分别返回清楚的用户提示。

## 4. 数据字段与照片生命周期

| 数据 | 服务端保存内容 | 用途与访问边界 |
|---|---|---|
| 账户 | 随机 ID、会话凭据哈希、创建时间、状态 | 邀请制访问和删除；不要求真实姓名 |
| 邀请码 | 哈希、有效期、可用次数、兑换状态 | 控制内测名额；兑换后不回显明文 |
| 用量 | 账户 ID、请求 ID、模型、状态、时间、耗时、token/费用估算 | 限额、防重复、成本监控；不记录图像内容 |
| 分析记录 | 账户 ID、结构化点评、五维分数、作者线索及置信度、时间 | 显示历史和处理删除请求；只对该账户可见 |
| 照片文件 | 私有对象键、文件类型、大小、创建时间、过期时间 | 分析与用户历史预览；无公开 URL，删除时清除派生文件 |
| 反馈 | 账户 ID、分析 ID、选项、用户文字、时间 | 质量改进；仅授权的项目维护者可访问 |

首轮正式用户图片不写入仓库、应用日志或公共资源目录。原件只在分析处理期间存在；分析预览使用私有存储并配置自动过期。用户可在页面删除单条分析，删除操作同时清除关联图片、点评和反馈。正式开放前必须在隐私说明里明确具体保留时长；该时长尚未确定，不能先填入产品文案。

日志仅保留随机账户标识、请求 ID、阶段、错误类别、模型、耗时和用量，不记录姓名、完整提示词、照片 Base64、永久图片链接或 EXIF/GPS。监控与备份访问限于管理员。

## 5. 必须完成的上线门槛

### 5–10 人邀请内测前

- 固定照片评测集通过，作者识别有“未识别”降级路径，低置信度标注不会误导。
- 邀请码、会话、限流、额度、幂等和管理员停用可验证。
- 用户可查看和删除自己的分析；删除覆盖数据库、图片和反馈关联。
- 用户隐私说明、服务说明、模型名称/备案信息的展示方式已确定。
- 分析失败分类明确；照片、意图和选项在重试时保留。
- 手机端完成真实照片流程验证；监控可看成功率、p50/p95 延迟、成本和错误类型。
- 部署有独立 staging/production 配置、密钥管理、备份和回滚方式。

### 本阶段明确不做

公开注册、付费、社区关系链、公开作品展示、模型训练、参数调色、复杂会员等级和微服务拆分。

## 6. 实施顺序

1. 对齐本方案与现有结果页决定，更新实施任务清单。
2. 实现账户会话、邀请码、额度和服务端幂等边界。
3. 实现服务端数据模型、私有图片生命周期、历史和删除。
4. 补齐监控、错误分类、成本上限和管理员停用能力。
5. 选择部署地域、云厂商和模型供应商，建立 staging；之后购买最小备案资源并提交备案。
6. 完成评测与手机端验收，邀请 5–10 位用户；复盘数据后再决定是否扩大到 30–100 人。

## 7. 尚待确定的部署参数

- 备案主体和域名归属。
- 云厂商及大陆部署地域。
- 生产视觉模型、数据位置和服务条款。
- 分析图片与历史记录的具体保存时长。
- 邀请码有效期、每人每日次数和全站日预算。

在上述参数确认前，架构保持供应商无关，不接真实用户生产数据，也不采购长期高配资源。
