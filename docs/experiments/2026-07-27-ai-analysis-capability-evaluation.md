# AI 摄影分析能力验证实验规格

日期：2026-07-27  
状态：实验实施  
范围：离线固定样例、结构化输出校验、坐标回绘与人工评估

## 1. 要回答的问题

本实验不验证完整产品，而只回答以下问题：

1. 多模态模型能否稳定识别主要主体，并给出可用的归一化主体框？
2. 模型能否只在确有视觉路径时画引导线，而不是为满足格式乱画？
3. 模型给出的裁切是否保守、可解释，并避免无意切断重要元素？
4. 分项评分与中文点评是否基于照片中的具体证据，而非通用模板？
5. 模型能否在位置判断不可靠时明确返回“不画”，且渲染端正确隐藏？

本实验不接账户、正式上传、支付、数据库、对象存储或生产模型供应商。
固定样例不是用户照片，也不代表用户同意训练。

## 2. 最小评测集

首轮使用 12 个固定槽位，覆盖可靠坐标最容易失效的边界情形：

| ID | 语境 | 关键挑战 | 期望的“不画”机会 |
| --- | --- | --- | --- |
| `landscape-s-curve` | 风光 | S 形河流、远山、多个视觉层次 | 主体框可不画或只框山体 |
| `landscape-single-peak` | 风光 | 单峰、湖面、低对比 | 无明确引导线时不画 |
| `railway-layered-scene` | 城市/纪实 | 多车厢、轨道弧线、远景建筑 | 主体框不应只框一个小车厢 |
| `street-single-person` | 街头 | 单人物、清楚负空间 | 无真实线性结构时不画引导线 |
| `street-multiple-people` | 街头 | 多主体、遮挡、边缘人物 | 主体不确定时不强画单框 |
| `street-reflection` | 街头 | 反射与真实空间混合 | 无法区分空间时不画主体框 |
| `documentary-occlusion` | 纪实 | 主体被遮挡 | 框应覆盖可见主体或不画 |
| `urban-symmetry` | 城市空间 | 中轴、重复结构 | 引导线应贴合真实结构 |
| `urban-diagonal` | 城市空间 | 强斜线、倾斜地平线 | 不把倾斜自动判为错误 |
| `travel-backlight` | 旅行 | 逆光剪影、暗部丢失 | 低可辨识主体时不画 |
| `minimal-small-subject` | 日常 | 极小主体、大面积留白 | 主体框不能扩成整幅 |
| `abstract-no-subject` | 实验/抽象 | 无明确主体与叙事中心 | 主体框和裁切都允许不画 |

### 2.1 照片准入规则

- 只使用公共领域、CC0、明确书面授权或团队自行拍摄且专为测试授权的照片。
- 不使用真实用户照片、社交平台抓取图、来源不明图片或带有精确 GPS 的原文件。
- 每张照片在 `dataset.json` 中记录来源、权利状态、授权证据说明和本地相对路径。
- 进入模型前生成最长边不超过 2048 像素、移除精确 GPS 的评测副本；原始来源文件不提交到实验目录。
- 同一固定集用于不同模型/提示版本回归；若替换照片，必须提升数据集版本并说明原因。
- 首轮 12 张，达到可运行门槛后扩充到 20 张，再扩展为产品规格要求的至少 100 张。

仓库内仅附带三张既有原型使用的公共领域样例。其余九个槽位是待补齐清单，
实验页会明确显示缺图，而不会用生成图冒充摄影作品。

## 3. 输出契约

契约文件为 `experiments/ai-analysis-eval/schema/analysis-result.schema.json`。
所有坐标使用原图方向下的 `[0, 1]` 归一化值。

顶层必须包含：

- `overall_score`：0–100 整数，仅作快速索引；
- `dimension_scores`：构图、光线、色彩与影调、叙事、技术质量，每项都含分数、依据、建议和置信度；
- `subject_boxes`：主体框判断；
- `leading_lines`：引导线判断；
- `crop_boxes`：裁切框判断；
- `observations`：只写可直接观察事实；
- `interpretations`：基于摄影知识的解释；
- `subjective_judgments`：明确标记的审美判断与替代解读；
- `suggestions`：可执行建议，回答改什么、为什么、如何验证；
- `confidence`：整体及各坐标类型置信度。

每个坐标对象都必须有 `decision: "draw" | "omit"`：

- `draw`：必须提供几何数据、依据和置信度；
- `omit`：几何数据必须为 `null`，并提供 `omit_reason`；
- 坐标置信度低于 `0.55` 时只允许 `omit`；
- 渲染器还会再次执行阈值判断，防止不合规结果误画。

裁切候选必须声明裁切损失比例，首轮只接受不超过 25% 的保守裁切。
实验阶段最多展示两个候选，但默认 mock 只提供一个保守方案。

## 4. 模型接口边界

实验台不内置模型 SDK。未来适配器只需实现：

```text
analyze(photo_path, context, schema) -> analysis-result.json
```

适配器必须：

1. 通过统一入口接收模型名、版本、提示版本和本地评测图；
2. 不在结果中保留图片二进制、外部永久 URL 或完整 EXIF；
3. 先做 JSON Schema 校验，再运行实验的语义校验；
4. 不合规结果写入独立失败目录，不交给渲染器；
5. 记录延迟和估算成本，但不记录可识别照片内容。

首轮建议对阿里云百炼 Qwen-VL 与火山方舟豆包视觉理解使用相同固定集，
供应商接入前另行确认备案、数据位置、内容使用政策与费用。

## 5. 人工评估

每张照片由至少两名评估者独立判断。评估表使用 0/1/2 分：

- 主体框准确：0 错误或误导；1 大致正确但过松/过紧；2 准确覆盖主要主体；
- 引导线克制：0 乱画；1 有依据但偏离明显；2 贴合真实视觉路径，或正确不画；
- 裁切保守：0 破坏关键内容；1 可用但损失偏大；2 保留意图且变化可解释，或正确不画；
- 文案具体：0 可套用任何照片；1 部分锚定画面；2 多处引用可核验细节；
- 非模板化：0 高度重复；1 有少量照片特征；2 语言与该图的结构、时机或语境相符；
- 低置信度隐藏：0 仍展示误导坐标；1 隐藏部分；2 所有低置信度坐标均隐藏。

另记录严重错误：

- 编造不存在的人、物、光线或关系；
- 把主观审美写成客观事实；
- 建议默认新增、移除或替换真实画面内容；
- 引导线或裁切框与文字依据互相矛盾；
- 低于阈值仍画坐标。

## 6. 首轮通过门槛

这是小样本能力筛选，不是生产验收。三张内置样例只验证工具链可用；
补齐 12 张并完成双人盲评后，模型/提示组合同时达到以下条件才建议进入功能 MVP：

- 主体框平均分不低于 1.6/2，且严重主体误框率不高于 5%；
- 引导线克制平均分不低于 1.7/2，乱画率不高于 5%；
- 裁切保守平均分不低于 1.7/2，无切断关键主体的严重错误；
- 文案具体与非模板化平均分均不低于 1.5/2；
- 低置信度隐藏通过率 100%；
- 事实编造、越权生成建议和坐标阈值违规均为 0。

若坐标能力不达标，但文字点评达标，产品应降级为只展示文字证据，
不得为了视觉效果强行上线框线。

## 7. 可复现实验记录

每次评测保存：

- 数据集版本与照片 ID；
- 模型、模型版本、提示版本和 schema 版本；
- 原始结构化 JSON 与校验结果；
- 人工评估 CSV；
- 汇总指标和严重错误列表。

版本之间使用同一照片 ID 对比，不能只挑选新版本表现较好的样例。
