# 中文摄影教练产品设计规格

日期：2026-07-22
状态：已批准（2026-07-22）
范围：交互原型、功能 MVP 与封闭测试

## 1. 设计目标

构建一个邀请制中文网页，让摄影爱好者上传自己的照片与创作意图，得到锚定到原图证据的摄影分析、可控裁切、重拍位置建议和反馈记录。

首版验证的核心不是“AI 能否写出摄影术语”，而是用户是否认为建议具体、可信，并愿意根据建议再次拍摄或上传。

## 2. 非目标

首版不建设完整摄影社区，不处理 RAW 显影，不训练自有大模型，不提供具体在世摄影师的一键模仿，不用生成式 AI 无痕修改用户照片，也不建立付费专家市场。

## 3. 用户流程

### 3.1 进入与上传

用户通过邀请制账户进入，上传一张 JPEG、PNG 或 HEIC 图片，单文件上限20MB。客户端在上传前展示隐私说明，并允许用户选择是否移除全部 EXIF；服务端始终丢弃精确 GPS。

当前暂定上传与创作上下文使用同一页面完成，不拆成多步向导。桌面端照片区域约占42%，表单区域约占58%，优先保证文字阅读和填写空间；窄屏改为上下排列，照片预览高度控制在约210像素。页面必须直接说明照片默认私密、原图生命周期和精确位置处理方式。

### 3.2 提供创作上下文

用户在上传页填写最多200字的创作意图，并从街头、纪实、人像、风光、城市空间或“不确定”中选择一个主要语境。创作意图与类型均为选填；全部跳过时，系统按通用摄影基础分析。页面使用日常语言引导用户描述拍摄时的感觉、犹豫或最希望保留的部分，不要求使用摄影术语。

### 3.3 分析

系统生成标准化预览，调用模型网关完成初步事实提取，再结合摄影评价规则生成结构化分析。低置信度位置不输出精确框，存在多种合理解读时并列展示。

分析过程不跳转到独立状态页。用户点击“开始分析”后，上传页原地进入只读状态：表单降低对比度并锁定，按钮从左向右以低透明度暗铜色填充，按钮文字始终位于填充层上方。文案随真实任务阶段依次切换为“正在读照片…”“正在看构图与光线…”“正在整理建议…”和“分析完成”，完成后进入结果页。没有可靠后端进度时只展示真实任务阶段，不伪造精确百分比；分析失败时恢复表单并提供“重新分析”，失败任务不扣使用额度。

### 3.4 查看结果

结果按以下顺序呈现：

1. 系统对创作意图的复述，允许用户纠正。
2. 画面描述：用二到四句具体描述照片中的主体、空间、关系和氛围，让用户确认系统确实读到了这张照片。
3. 百分制评分：展示总分，以及构图、光线、色彩与影调、叙事、技术质量五个分项。
4. 画面亮点：先确认已经成立的选择，最多三个，每项附图上或文字证据。
5. 可以再试试：最多三个优先改进点，每项解释影响与不改变原意的改法。
6. “如果重拍”：移动、等待、机位、人物或车辆位置框。
7. “现在还能做”：最多两个裁切方案与基础后期建议。
8. 另一种合理解读与整体置信度。

总分用于快速理解，不单独定义照片好坏。总分和每个分项都必须有证据、置信度与可执行建议，不能只返回数字。界面使用克制的主题色区分分数范围：85分及以上使用灰绿色，75至84分使用暖灰金色，75分以下使用低饱和砖红色；颜色只帮助扫读，不附带羞辱性标签。

### 3.5 反馈与复练

用户可对每条建议标记：准确、有帮助、误解意图、不适用。用户可以上传重拍或调整后的版本，与原分析建立关联。

### 3.6 可交互原型与真实动态的边界

固定样例原型不能停留在互不相连的静态页面。它必须串联“主页—上传与拍摄想法—分析状态—结果—裁切或参数建议—逐条反馈”的完整流程，并实现轮播、样例选择、表单输入、阶段进度、图层切换、裁切预览、参数面板和反馈状态等真实前端交互。交互状态只保存在浏览器内，刷新后可以重置。

该原型只使用已授权的本地样例照片和固定结构化数据，不接账户、真实上传、数据库、对象存储、模型调用、额度扣减或支付。图片、分析数据与错误状态均由本地夹具提供，不把模拟等待包装成真实 AI 处理。

功能 MVP 再接入数据层动态：真实照片上传、模型分析、账户与权限、使用额度、历史记录、删除和后续付费。原型阶段确定的页面状态和结构化结果契约应直接成为这些后端能力的前端接口边界，避免接入真实服务后重新设计整条流程。

## 4. 分析输出契约

模型返回必须满足内部结构化 schema，至少包含：

- `intent_summary`
- `photo_description`
- `overall_score`
- `score_summary`
- `observable_facts[]`
- `strengths[]`
- `priority_issues[]`
- `dimension_assessments[]`
- `reshoot_suggestions[]`
- `crop_candidates[]`
- `postprocess_suggestions[]`
- `alternative_reading`
- `confidence`
- `safety_flags[]`

`overall_score` 与每个 `dimension_assessments[].score` 使用0到100整数。评分必须同时返回依据、置信度和适用语境。每条建议包含类型、依据、影响、具体动作、置信度和可选的标准化坐标。坐标范围使用0到1，并经过服务端 schema 与边界校验。

自由文本不得直接触发图片变更、数据库权限或公开发布。

## 5. 评价框架

### 5.1 通用基础层

分析主体关系、视觉重心、边缘、线条、层次、遮挡、曝光、色彩关系、清晰度和技术缺陷。

### 5.2 创作意图层

判断形式是否服务用户说明的情绪、事件、关系或观察，而不是把主体突出等同于唯一正确答案。

### 5.3 摄影语境层

街头与纪实语境允许模糊、倾斜、遮挡、复杂边缘和多层元素成为有意表达。模型必须说明这些形式何时形成张力，何时只是缺乏控制。

### 5.4 不确定性

系统使用“观察事实—可能解释—建议”三段式表达。无法确认创作意图时先请求用户纠正，不给武断结论。

### 5.5 情绪价值与表达方式

分析先让用户感到作品被认真看见，再提出改进。输出顺序固定为具体描述、画面亮点、可以再试试；不使用“失败”“不专业”“没有价值”等羞辱性结论。

肯定必须锚定到照片中的具体选择，不能使用“很棒”“很有感觉”等空泛鼓励。改进建议采用邀请式语气，说明这是一种可尝试的方向，而不是唯一正确答案。描述需引用画面中特有的主体、位置、光线或关系，避免任何照片都能套用的固定模板。

## 6. 可视化与图像处理

### 6.1 图上标注

支持矩形、点、方向箭头、裁切框和文字锚点。标注层与原图分离，不改变原始像素。

### 6.2 裁切

系统最多生成两个候选裁切框：一个保守方案，一个更明显的重构方案。用户可以自由调整，并查看画幅比例和裁切损失。

### 6.3 教学模拟

功能 MVP 默认只提供位置框与方向提示。生成式场景模拟不在 MVP 中启用；后续启用时必须独立授权、明确水印并写入生成内容标识。

### 6.4 后期建议

MVP 只输出曝光、白平衡、对比、高光、阴影、饱和度和黑白转换等方向性建议，不生成相机专属配方或承诺精确复现参考风格。

## 7. 系统组件

### Web Client

负责账户访问、上传、意图输入、结果呈现、图层交互、裁切预览、反馈和历史记录。

### Application API

负责权限、上传授权、分析任务、数据访问、删除和审计事件。

### Image Pipeline

负责格式验证、恶意文件防护、预览生成、EXIF 清理、方向修正和原件生命周期。

### Analysis Orchestrator

负责事实提取、评价提示构建、模型调用、schema 校验、重试、低置信度降级和成本记录。

### Model Gateway

定义统一的视觉分析接口，并适配国内供应商。模型版本和请求成本写入内部审计数据，不暴露供应商格式给业务层。

### Result Renderer

把结构化建议转为五维评价、证据卡片、标注图层和裁切预览。

### Feedback & Evaluation

收集逐条反馈，维护固定测试集，比较模型、提示词和流程版本。

## 8. 数据模型

核心实体包括：

- User：账户、同意记录和产品偏好
- PhotoAsset：原件、预览、状态、保留期限和所有权
- AnalysisRequest：创作意图、摄影语境、模型版本和任务状态
- Critique：结构化分析结果、置信度和成本
- Annotation：独立图层与标准化坐标
- PhotoVersion：原图、重拍或用户调整版本之间的关系
- Feedback：用户对单条建议的判断
- ConsentRecord：公开、模型改进、生成式模拟的独立授权记录
- AuditEvent：删除、公开、模型调用和权限相关事件

MVP 不建立社区关注、评论、点赞或点评声望实体。

## 9. 隐私与安全

- 所有照片默认私密，使用不可猜测的短期签名 URL。
- 原件在分析完成后24小时内删除；预览最长边不超过2048像素。
- 精确 GPS 不落库，不写入日志。
- 用户可以删除单张记录或完整账户。
- 公开、训练和生成式处理分别授权，默认关闭。
- 模型供应商必须经过数据使用、存储区域和备案检查。
- 日志只记录任务 ID、模型、延迟、Token、错误码和匿名化质量指标。
- 上传内容进行格式、大小和解码验证；不信任文件扩展名或客户端 MIME。

## 10. 错误处理与降级

- 图片无法解码：拒绝分析并提供支持格式说明。
- 模型超时：有限次数重试，之后保留任务并允许用户重新提交。
- schema 不合法：自动修复一次；仍失败则不展示不完整结论。
- 坐标置信度不足：展示文字建议，不渲染误导性框。
- 模型理解与用户意图冲突：允许纠正意图后重新分析，不覆盖旧版本。
- 供应商不可用：切换到已通过评测的备用模型；没有备用时明确告知服务暂不可用。
- 内容安全命中：不公开传播，按适用规则提供安全提示和申诉路径。

## 11. 质量评测

### 固定评测集

建立至少100张已取得使用许可的测试照片，覆盖街头、旅行、日常纪实和城市空间，以及倾斜、遮挡、多层、模糊、极简和复杂边缘等构图情况。

### 评测维度

- 事实准确性
- 证据与结论一致性
- 建议具体性
- 是否尊重创作意图
- 复杂构图语境理解
- 不确定性表达
- 坐标可用性
- 中文自然度
- 画面描述具体性
- 肯定是否有证据且不空泛
- 改进语气是否清楚、尊重并提供情绪价值
- 评分与文字判断的一致性
- 响应时间和单次成本

### 回归门槛

任何模型、提示词或分析编排变更，不得提高严重事实错误率、越权生成率或隐私风险。帮助度提升必须在固定集与真实用户反馈中同时观察。

## 12. 测试策略

- 单元测试：schema、坐标、评价排序、权限和生命周期计算。
- 集成测试：上传到删除、模型适配、重试、供应商切换和反馈写入。
- 端到端测试：用户上传、纠正意图、查看标注、裁切、反馈和删除。
- 安全测试：越权访问、签名 URL、恶意图片、EXIF 泄露和日志泄露。
- 模型评测：固定集对比、人工抽检和低置信度降级。
- 视觉测试：不同画幅、移动端标注对齐、中文排版和深浅主题。

## 13. 发布方式

先发布固定样例的交互原型，再进入邀请制功能 MVP。封闭测试限制用户和每日分析次数，并显示 Beta 说明。每次发布保留模型版本、提示版本和单位成本，出现质量回退时可以恢复上一分析配置。

## 14. 商业化与额度策略

当前采用“首次完整体验、日常免费基础点评、会员解锁深度能力”的方向，但在现阶段不上线真实付费、额度扣减或支付流程。

- 新用户获得3次完整基础点评体验，用不同照片理解产品价值。
- 体验额度用完后，日常免费额度为每天1次基础分析。
- 未来会员方案暂按每天3次或每月30次深度分析设计，超出后可购买次数包；具体价格和额度必须根据封闭测试数据确定。
- 免费结果必须包含有实际价值的照片描述、总分、分项评分、亮点、一个改进点和一个关键图层，不能在上传后只显示分数再锁住全部解释。
- 深度能力包括完整图上证据、更多裁切方案、参数调整、追问、重拍对比、长期历史和成长档案。

固定样例原型只预留“完整点评体验3次”“今日基础分析1次”的视觉位置，不限制操作。真实额度与付费只能在照片隐私链路、国内模型、成本记录和固定评测集全部通过验证后进入邀请制测试。首轮邀请30至100名用户比较免费额度、复用率和付费意愿，再决定价格与最终分层。

不使用广告、出售照片数据或默认授权模型训练作为商业化方式。

## 15. 成功与停止条件

达到项目书中的30名用户、14天复用、建议帮助度和重拍行为指标后，进入审美档案与轻社区设计。

若用户只使用一次评分、很少查看证据、没有根据建议重拍，项目应先修正核心价值，不继续扩建社区或 RAW 功能。
