# 中文摄影教练实施计划索引

设计规格于 2026-07-22 获项目发起人批准。本索引把互相独立、可单独验收的工作拆开，避免在尚未验证私人教练价值前开发社区、RAW 或生成式修图。

## 已选技术路线

- Web 与应用 API：TypeScript、Node.js 24 LTS、Next.js 16（App Router）。初期以同一应用部署，代码边界按 Web Client、Application API、Image Pipeline、Analysis Orchestrator、Model Gateway 划分；不预设微服务。
- 数据与任务：PostgreSQL 17、Drizzle ORM、pg-boss。任务队列复用 PostgreSQL，MVP 不增加 Redis 运维面。
- 文件：S3 兼容对象存储抽象；本地测试用 MinIO，生产接入经评估的中国大陆 OSS。原件与预览使用不同前缀、不同保留策略。
- 校验与测试：Zod、Vitest、Playwright；严格 TypeScript、ESLint、Prettier。视觉回归只使用已授权的合成或测试图片。
- 模型：内部 `ModelGateway` 契约；先实现 Qwen-VL 与豆包视觉理解适配器，选择生产模型前以固定评测集比较质量、延迟、成本、数据位置与备案状态。

上述选择仅用于当前原型和 MVP；任何新的云服务、模型供应商、邮件服务或生成式图像能力，必须先补 ADR，记录成本、数据位置、内容政策和替代方案。

## 计划与门槛

1. [阶段 1：固定样例动态前端原型](2026-07-23-stage-1-dynamic-frontend-prototype.md)：不收集账户或真实照片，不调用模型；实现主页、分析阶段、百分制评分、证据图层、裁切/参数参考和建议反馈的完整浏览器交互。退出条件为 5 名目标用户无讲解完成流程并复述差异，不要求上传重拍或修改版本。
2. 阶段 2：功能 MVP：在阶段 1 通过后，根据原型测试证据细化 API 契约与信息架构，再执行上传、隐私生命周期、模型网关、分析、历史与删除的实施计划。
3. 阶段 3：封闭测试：仅在阶段 2 的安全、删除、模型评测和权限门槛通过后，建立邀请、配额、成本监控、人工抽检与回归发布流程。

阶段 2 和 3 依赖阶段 1 的真实可用性结果，不能在当前以假设替代；届时应新建计划并引用本索引和原型研究结果。社区、专业内容、RAW、风格复制和生成式教学模拟不在这三阶段的开发范围内。
