# 暗房本地 MVP 实施计划

日期：2026-08-24  
依据：[本地 MVP 设计规格](2026-08-24-local-mvp-design.md)  
状态：执行中

## 技术选择

复用已批准旧原型的 Next.js 16、React 19、TypeScript、Zod、Vitest 和 Playwright，不增加新的前端框架。业务应用放在 `develop/app`；模型评测继续留在 `experiments/ai-analysis-eval`。

浏览器负责选择照片、完整画幅预览、方向修正和生成压缩副本。本地 Next.js 服务负责模型适配、提示构建、结构化校验和错误降级，浏览器不接触 API key。

## 里程碑 1：真实照片输入

1. 迁移旧暗房原型到 `develop/app`，替换工作名和固定样例标识。
2. 先写图片尺寸规划测试，覆盖横图、竖图、小图和异常尺寸。
3. 实现本地文件选择、类型/大小校验、完整 `contain` 预览和最长边 2048px 的压缩副本。
4. 保存临时分析上下文，刷新或离开后可清理，不把图片写入仓库。

退出条件：横图、竖图、方图和超大图均完整显示；小图不放大；发送体积与尺寸在界面可见。

## 里程碑 2：本地模型分析

1. 定义页面使用的分析请求和结果 schema。
2. 在独立服务端适配层接入 Qwen，不让页面依赖供应商响应格式。
3. 将可观察事实与可选创作意图分层传入模型。
4. 加入超时、有限重试、响应校验和用户可理解的错误状态。

退出条件：用户只需启动本地服务并在页面选择照片，不再手输照片 ID 或长终端命令。

## 里程碑 3：结果体验

1. 用真实结果驱动整体分数和五维颜色刻度。
2. 保持照片完整显示，标注绑定图片实际渲染区域。
3. 分开事实、解释、意图关系、替代解读、拍摄建议和后期建议。
4. 低置信度标注降级为文字，裁切默认关闭且可撤销。

退出条件：评分长条、证据文字和图片可以相互核对；不会重复固定总分免责声明。

## 里程碑 4：验证与交付

1. 运行单元测试、类型检查和静态检查。
2. 使用至少一张横图、一张竖图、一张大图和一张复杂构图照片完成浏览器验证。
3. 检查桌面与移动端截图、图片非空、文字不重叠、标注不漂移。
4. 提供一个简短启动脚本和本地访问地址。

退出条件：核心流程在本机可重复运行，错误无需通过 `Control-C` 恢复。
